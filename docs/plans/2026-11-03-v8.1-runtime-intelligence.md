# uneXpected v8.1 Runtime Intelligence — Implementation Plan

> **For agentic workers:** Execute task-by-task on the isolated feature branch. Each task has a focused test gate and is not complete until its verification evidence is recorded.

**Goal:** Complete the safe LibreChat-inspired runtime foundations—governed external-tool adapter boundary, isolated child runs, and durable task traces/reconnect reads—without splitting the one-application v8 architecture or enabling consequential actions.

**Architecture:** Extend the existing Python command center, Coordinator, role registry, capability registry, and SQLite/PostgreSQL StateStore implementations. All integrations are host-registered adapters; skills and connector metadata never grant permissions. Persistent task/event rows remain authoritative, and reconnect is read-only so it cannot replay task effects.

**Tech Stack:** Python 3.10+, standard-library interfaces, existing SQLite/PostgreSQL adapters, unittest, GitHub Actions, single-process Docker image.

## Global Constraints

- Keep the single Python application, single Coordinator, 38-role registry, one API boundary and one authoritative state layer.
- Preserve manifest v1/v2 compatibility and the existing hash-pinned Skill bundle implementation on the parent branch.
- Do not add MongoDB, Redis, ClickHouse, a separate RAG API, another frontend, phone/PWA assets or another runtime service.
- No connector network session or external server is activated by registering an adapter. No package auto-install or upstream auto-sync.
- Every tool invocation is bound to an enabled, provenance-verified capability, requesting role, action digest, task, deadline, cancellation token and bounded input/output.
- Privileged scopes continue to require host-verified action-bound approval. Children never inherit broader authority than their own role and action policy.
- External tool results, documents, and skill content are untrusted evidence, never instructions.
- Do not store credentials, bearer tokens, raw secrets or unbounded provider payloads in events.
- No code execution, scheduled automation, publishing, payments, external messaging, destructive operations, deployment, merge or service retirement is enabled by this work.
- Keep all changes on `feat/v8.1-runtime-intelligence`, stacked on `feat/v8.1-advanced-skills`. Do not target legacy v7 `main`.
